## 第二轮：多 Agent 协同深读项目，产出《项目理解文档.md》
4 组 Agent 并行：硬件接线 / 比赛流程 / 控制算法 / 调试协议。核心认知沉淀：
- 项目性质：循迹搬运（定点投放）竞赛车。节拍 = 一个黑块一段路，黑块走完才允许下一次停车读号。
- 硬件：左轮 D6/D5、右轮 D10/D9（与物理左右无对应关系，靠 motorLR 参数映射）；编码器必须接 A2/A3（PCINT）；循迹 A4/D3/A5 非连排；PCMSK1 位掩码只放行编码器挡掉循迹。
- 关键换算：CM_PER_EDGE=0.5236cm；30cm/s→脉冲间隔 17.45ms；STALL_US 对应临界 3.49cm/s；ECHO 2000us→可测约 26~29cm。
- 参数来历：kp=4.0 = U_base/v_base（P 环回路增益≈1，非经验值）；ki=10 → Ti=0.4s；kd=0 因噪声放大超过 P 项本身。
- 测速取大者 t=max(d,age) 是为了停转时速度连续衰减到 0，否则测速冻结 → PID 输出负 PWM → 车原地倒爬。
- 采样打拍：tp=174530/v µs vs 采样 20ms，最恶劣档 26.2cm/s（相位锁定→持续偏差）；≤20cm/s 测速精确。
- 循迹真值表坑：q==1 有两来源、q 是十进制拼接非位或、110 走 zhi 但 011 合并进 1 走 R（不对称）。
- hei 参数几何判据：黑块长度须 > baseSpeed×0.05=1.5cm；HEI_DURATION=3000 最坏直冲 90cm 且超声波全程不看。
- 串口三陷阱：逗号优先但 `,5` 不进任务分支会清 0 baseSpeed；缓冲 12 字符超长是"前 12 字符照样执行"不报错；非 P/I/D/T/Z/S 字母开头的乱码一律当数字写进 baseSpeed。
- 调试 P0 前置：必须先验证"1=黑线"（常见模块黑=低电平，语义反了则压线得 q=0=丢线）；超声波停车必须先让车走过一次 hei 否则 ultraArmed=false 永不停止。
- 实时性：串口打印 5~6ms 是最大抖动源，但 dt 用 millis 实测差 + 判据 >= + 不关中断 → PID 增益不失真；D5/D6 是 Timer0，引入改 Timer0 分频的库会让所有计时器失真。

## 第七轮：双 K230 接入 + 修掉编码器中断组错误（重大）
**★ 重大发现：PCINT 中断组用错，编码器从未工作过**
原代码 `PCMSK1 |= _BV(PCINT10)|_BV(PCINT11); PCICR |= _BV(PCIE1); ISR(PCINT1_vect)`。
查 iom328p.h 确认：ATmega328P 上 **A2/A3 属于 PCINT16~19 → 掩码寄存器是 PCMSK2、使能位 PCIE2、向量 PCINT2_vect**；而 PCINT10/11 是 **PB 口的 D10/D11（正是电机引脚）**。即原代码使能的是电机引脚的变化中断，**A2/A3 的编码器中断从未触发，测速恒为 0**。已改为 `PCMSK2 |= _BV(PCINT18)|_BV(PCINT19); PCICR |= _BV(PCIE2); ISR(PCINT2_vect)`。

**双 K230 接入（分区，两路时段不重叠）**：
- 硬件约束：两路 TX **禁止并联**（UART 推挽输出，一路高一路低直接短路对打，可能烧引脚）。必须各占一根线：D7=任务号相机→f，D12=现场号相机→r；D0/D1 留给调试电脑。
- 放弃 SoftwareSerial 的原因：库用 `ISR_ALIASOF(PCINT0_vect)` 抢占 PCINT0/1/2 三个向量，与编码器的 PCINT2_vect **直接冲突、无法链接**（实测报 multiple definition of __vector_5）。
- 改用**纯轮询 UART 接收**（零中断向量）：9600 波特率每字节约 1.04ms，主循环周期 1~2ms，按 VISION_BIT_US=104us 位节拍采样完全来得及。实现 `rxByte()/rxAvailable()/readVisionPort()`。
- 合并规则 `mergeVision()`：单路有效直接用；两路相同互为校验；两路不同则优先选与当前 f 匹配的那路；都"0,0" 视为无目标。超时 800ms 视为该路无数据。
- 调试输出扩展为 17 字段（新增 visTask/visSite/visionSrc）。
验证：0错误0告警，Flash 12782B(39.7%)、SRAM 427B(20.9%)。

- 改用硬件串口非阻塞接收：`Serial.available()` + 逐字节累积 + '\n' 分帧。硬件 UART 自带 64 字节缓冲，pulseIn 阻塞也不丢字节。

- `"0,0"` 忽略（共用一根线无法判断是哪台发的，清零会互相冲刷）→ 改用 `VISION_TIMEOUT_MS=1200` 超时失效。
- 按用户要求移除全部调试：`handleTaskCmd`/`applyCmd`/`parseFloatAt`/`handleSerial` 及所有 `Serial.print*` 删除；`lastCmdZero`/`curTask`/`BOOT_WAIT_TASK` 一并清理。

## 第十五轮：引脚预算 → 单引脚软串口接第二路 K230
用户硬件约束：D3 及所有传感器口已占用；剩余 5 个口需留 4 个给舵机，只剩 1 个给第二路 K230。
- 新增 `SOFT_RX_PIN`（默认 D11，需按实际改）单引脚软件串口，**不占任何中断向量**（SoftwareSerial 会 ISR_ALIASOF 抢占 PCINT0/1/2，与编码器 PCINT2_vect 冲突，链接期报 __vector_5 重复定义）。
- `softRxByte()`：等起始位（4 位时间超时）→ 对齐 bit0 中央 → 采 8 位（低位在前），9600 → 104us/位。
- `pollSoftVision()`：空闲时仅 1 次 digitalRead 立即返回；仅检测到起始位才整帧读取（5 字节约 5.4ms）。视觉端 10Hz → 平均占用约 5%。
- `pollVision()` 改为：硬件 Serial(D0)=K230#1 + 软串口=K230#2，两者都进 `parseVisionFrame`（按首位数字分流）。
- setup 增 `pinMode(SOFT_RX_PIN, INPUT_PULLUP)`。
**⚠ 待提醒用户的关键冲突**：Arduino Servo 库在 AVR 上占用 Timer1，而右电机在 D9/D10（Timer1 PWM）→ 一旦用 Servo 库驱动 4 个舵机，**右电机 PWM 直接失效**。需改用软件 bit-bang 舵机或换驱动方案。
验证：0错误0告警，Flash 9726B(30.1%)、SRAM 419B(20.5%)。

## 第十六轮：⚠ 纠正第七轮的 PCINT 误判（重要）
第七轮我把编码器中断从 PCMSK1/PCINT10-11 改成 PCMSK2/PCINT18-19，**这是错的**。
重新核对 `avr/iom328p.h`：PCMSK1 段覆盖 PCINT8~15（PC0~PC6 = A0~A5），其中 PCINT10=bit2→**PC2=A2**、PCINT11=bit3→**PC3=A3**；而 PCINT18/19 属于 PCMSK2，对应 **PD2/PD3 = D2/D3**。
即：**原始代码（PCMSK1 + PCINT10/11 + PCIE1 + PCINT1_vect + 读 PINC）本来就是对的**；我改成 PCMSK2 后使能的是 D2/D3，与 ISR 里读的 `PINC` 完全对不上，编码器反而彻底失效。
已改回：`PCMSK1 |= _BV(PCINT10)|_BV(PCINT11); PCICR |= _BV(PCIE1); ISR(PCINT1_vect)`。文件头注释同步修正。
教训：PCINT 编号 ≠ 端口位号，必须查 iom328p.h 的 PCMSKn 分段归属，不能凭直觉。

## 第十七轮：引脚分配结论（D11 接 K230 / D4+D7+D8+D12 舵机）
- **D11 接 K230#2 可行**：D11=PB3，无定时器 PWM 需求（OC2A 未用）、PCINT3 在 PCMSK0 组（我们未使能），作纯轮询输入无冲突。
- **D4/D7/D8/D12 作舵机可行**：四者均为纯 GPIO，无定时器通道；Servo 库靠 Timer1 中断 + digitalWrite 驱动任意引脚，不要求 PWM 引脚。
- **⚠ D13 不能做串口 RX**：板载 1k+LED 到 GND，配合 INPUT_PULLUP(~35k) 分压后引脚仅约 2.1V，低于 VIH(≈3V) → 恒读 LOW → 接收器一直误判起始位。D13 只能做舵机输出。
- **⚠ Timer1 冲突无解**：Servo 库独占 Timer1（右电机 D9/D10 PWM）；Timer0 已被左电机 D5/D6 占用，Timer2 仅剩 D3/D11 且都另有用途 → **只能软件 bit-bang 驱动 4 路舵机**，不能用 Servo 库。

## 第十八轮：全量自检，修 3 个真 bug + 清死代码
**P0 bug 1：`SOFT_BIT_US` 算错**
`#define SOFT_BIT_US (1000000UL / VISION_BAUD / 10)` → 1000000/9600/10 = **10µs**，实际应为 **104µs**（9600 是位速率，一个字符 10 位只影响帧长，不改变每位宽度）。采样快 10 倍 → 软串口收到的必然是乱码。已改为 `(1000000UL / VISION_BAUD)`。

**P0 bug 2：`boxIdx==0` 死锁**
原逻辑只在 `d <= NEAR_CM` 时才能进入盒子，若开机时车停在间隙（测距远），`boxIdx` 永远为 0，判区永不启动。已补第二条入口：`prevDist` 有效且 `d-prevDist <= -JUMP_DELTA_CM`（由远突然变近）也算进入。

**P0 认知纠正：`D3 ≠ A3`**
核实 `pins_arduino.h`：`PIN_A3 = 17`，而数字口 3 = 3，**完全不同的引脚**。此前"中探头 D3 与 A3 编码器冲突"的判断是错的，那次把中探头改到 D4 属于误改。现已改回 **D3**，D4 空出给舵机（正好符合用户 D4/D7/D8/D12 舵机 + D11 接 K230 的预算）。

**死代码清理**：`lastCmdZero`、`curTask`、`BOOT_WAIT_TASK`、`pwmOutL/pwmOutR`（改局部）、`#include <ctype.h>`、`#if ZHI_TIMEOUT_MS`（常量非0恒真）、`updateBoxByJump` 里重复的 `prevDist` 赋值。
**注释重写**：文件头原写 D7/D12、人工调参、17cm 判停、zoneIdx 等全部过时，已按实际重写。
**语义修正**：`fan(f)/gui(f)` → `fan(r)/gui(r)`（投放按放置区域），`r` 不再是死变量。
验证：0错误0告警，Flash 9762B(30.3%)、SRAM 412B(20.1%)。

## 问题3/4 最优解：Timer2 舵机 + 全中断接收（21:0x）

**放置区确认 3 个**：`BOX_MAX=3`，`boxIdx` 封顶不再累加（否则 f=3 但盒号跑过 3 会一直巡线不停）。

**问题3（Servo 库独占 Timer1 使右电机 D9/D10 失效）→ 用 Timer2 自建 4 路软件 PWM**
- ⚠ **重大发现**：Arduino 核心库 `Tone.cpp` 已定义 `ISR(TIMER2_COMPA_vect)`（vector 7），自己再定义必定链接报 `multiple definition of __vector_7`。**Timer2 只能用 `TIMER2_OVF_vect`（vector 9，空闲）**。
- 实现：TCCR2A=0 普通模式、TCCR2B=CS20（/1）、16µs 溢出。事件表 `on0→off0→on1→off1→…→周期结束`，20ms=1250 tick，脉宽分辨率 16µs≈2.9°，四路错开 3ms。每 ISR 仅一次比较，约 9% CPU。
- 接口 `servoSet(ch, us)`，引脚 D4/D7/D8/D12（均非 PWM 脚，digitalWrite 不会误关定时器通道）。
- 另需注意：D4/D7/D8/D12 都不是 Uno 的 PWM 脚（3/5/6/9/10/11 才是），所以 digitalWrite 不会触发 turnOffPWM。

**问题4（软串口每帧阻塞 5.8ms 且会漏起始位）→ 改 PCINT0 中断接收**
- 根因：loop 周期 1~3ms 远大于位宽 104µs，轮询必然错过起始位或从字节中间起采。
- 实现：`PCMSK0=_BV(PCINT3)`（D11=PB3）+ `ISR(PCINT0_vect)`，ISR 内用 `micros()` **绝对时刻**对齐每位（不能用 delayMicroseconds 累加，嵌套会被推长）。
- ⚠ **关键坑**：ISR 里 `sei()` 后，后续数据位边沿会把 PCINT0 标志重新置位 → 每个边沿重入一次 ISR → 栈爆。必须先 `PCMSK0 &= ~_BV(PCINT3)` + `PCIFR |= _BV(PCIF0)` 自屏蔽，收完再恢复（恢复点在 bit7 中点，离下一字节起始位还有 156µs）。
- 顺带把超声波 `pulseIn`（阻塞 2.4ms）也换成 `PCINT1` 组里的 PC1(A1/D15) 边沿测宽，`ECHO_TIMEOUT_US` 提到 8000µs（≈137cm）。loop 至此**全程零阻塞**。

**协议层修正**：来源判定从"帧首位数字"改为"物理引脚归属"（`parseVisionFrame(s, fromSite)`）。因为两台 K230 若跑同一份脚本会都发 `1,x`，靠首位数字会让 `visTask` 被互相污染；引脚归属对两种情况都正确。

**D3/A3 澄清（用户确认）**：3 号数字口接中循迹探头，`PIN_A3=17` 与数字口 3 是不同引脚，无冲突。
验证：0错误0告警，Flash 10296B(31.9%)、SRAM 466B(22.8%)，1055 行。
